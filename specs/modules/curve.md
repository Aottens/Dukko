# Module spec: curve (CURV)

Status: **CURV-01, 02, 03 proposed 2026-10-29 (VS2-03), awaiting owner approval**; the rest is a draft carried over from the 2026-05-03 requirements; the owner approves each criterion when its task starts (gate 1).

## Definitions
- **Curve value** `c` ∈ [0, 1] at phase `p` ∈ [0, 1): how far the duck is in (1 = fully ducked), as in `dsp.md`.
- **Point** `{x, y, tension}`: `x` is a phase in [0, 1), `y` a curve value in [0, 1], `tension` in [−1, 1] shapes the segment from this point to the next. Values outside their range are clamped when the curve is read.
- **Segment shape**: from point `(x0, y0, t)` to the next point `(x1, y1)`, with `u = (x − x0) / (x1 − x0)`, the value is `c = y0 + (y1 − y0) × s(u)` where `s(u) = (e^(10·t·u) − 1) / (e^(10·t) − 1)`, and `s(u) = u` for `t = 0`. Positive tension starts slow and ends fast; `−t` mirrors it: `s₋ₜ(u) = 1 − sₜ(1 − u)`.

## Acceptance criteria

- **CURV-01** `dsp::Curve` (in `source/dsp/`, no JUCE) is a list of points and evaluates in closed form: `value(p)` for any phase (wrapped into [0, 1)). Points are taken in order of `x` (stable for equal `x`); the curve is periodic, so the last point connects to the first point at `x + 1`, and before the first point the curve is on that wrap segment. No points gives `c = 0` everywhere; one point gives its `y` everywhere. `value` at a point's `x` is its `y`; at tension 0 the midpoint of a segment is the mean of its ends; at tension 0.5 and `u = 0.5` the value follows the segment shape; tension `−t` mirrors `t`; `y = 2` reads as 1. The default curve `Curve::sine()` is `(0, 1, 0.17)`, `(0.25, 0.5, −0.17)`, `(0.5, 0, 0.17)`, `(0.75, 0.5, −0.17)`: it is 1, 0.5, 0 and 0.5 at phase 0, 0.25, 0.5 and 0.75 and stays within 0.025 of DSP-01's raised cosine. The model is plain data (three floats per point); its place in the saved state comes with the user curve (CURV-05).
- **CURV-02** The audio thread reads the curve from a `dsp::CurveSnapshot`: 1024 floats, entry `i` = `value(i / 1024)`. Lookup at phase `p` interpolates linearly between entry `⌊1024p⌋` and the next, entry 1023 wrapping to entry 0; for `Curve::sine()` it differs from `value(p)` by less than 0.001 at 10 000 phases. `dsp::CurveFeed` hands snapshots over without locks, allocation or waiting: it holds three snapshots inline (a triple buffer). `publish (const Curve&)`, called from one thread only (the message thread), renders into its own slot and exchanges it with the shared slot through one lock-free `std::atomic<int>`; the audio thread takes the shared slot at block start, only when a new one is there, through the same exchange. The newest publish wins: two publishes before a block start give the second. With one thread publishing 10 000 flat curves and another taking and reading them in a loop, every snapshot read has all 1024 entries equal (no torn snapshot). The processor publishes `Curve::sine()` in its constructor and ducks with the feed's value instead of DSP-01's fixed cosine; DSP-01's processor tests and DSP-06's allocation guard stay green.
- **CURV-03** When the feed takes a new snapshot it crossfades: for 10 ms (`round(0.01 × rate)` samples, 480 at 48 kHz) the value is `old(p) × (1 − f) + new(p) × f`, with `f` rising by `1/480` per sample and exactly the new value from sample 480 on. A snapshot published during a crossfade is taken at the first block start after it ends. After `prepare` the newest snapshot is used directly, without a crossfade. At 48 kHz and a fixed phase, a switch from a flat 0 curve to a flat 1 curve moves by no more than 1/480 per sample and is exactly 1 at sample 480; a flat 0.5 curve published during that fade is not heard before it ends and then fades in the same way. The click check by ear belongs to UI-07, when the editor can change the curve; until then nothing in the plugin publishes after the constructor, so there is no Bitwig run for this criterion.
- **CURV-04** Factory preset library covers the Kickstart-1 family at minimum: sine, low pulse, high punch, sidechain-style — baked as `static constexpr` data
- **CURV-05** Exactly one user-editable curve slot per plugin instance for v1
- **CURV-06** Visual curve display reflects the active curve (factory or user) accurately
- **CURV-07** Live playhead overlay on curve display follows host transport at ~60 Hz
